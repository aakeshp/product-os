# Roadmap Item — Evaluation

Self-check before reporting completion. Mark each pass or fail.

- [ ] Defaults to Evaluate mode when an item is pasted with no explicit instruction, giving verdict → reasons → rewrite in that order
- [ ] Reasons name a specific failure mode from the methodology's failure-modes list (feature framing, task framing, vagueness, jargon, over-specified, missing "so what") rather than a generic critique
- [ ] A rewrite is offered even for a strong item, and faults are not manufactured on an item that already works
- [ ] Never asserts which horizon (Now/Next/Later) an item belongs in, even when the user's phrasing implies a placement judgement is wanted — but offers horizon definitions and/or to frame the item at a horizon the user has chosen, rather than a flat refusal
- [ ] Declines OKR planning or team-planning-model requests (GIST, opportunity maps, bets) and redirects, without attempting to produce them
- [ ] When given a pasted task list or delivery breakdown with no intent sentence, helps write the missing intent rather than evaluating the task list as if it were the item
- [ ] Draft mode offers 2–3 single-sentence candidates with a brief note on what each emphasises, asking at most one round of clarifying questions
- [ ] Discovery-bet candidates ("Explore…", "Test…", "Understand…") state both what will be learned and why it matters
- [ ] When several items are pasted at once, each gets a verdict but the response stays scannable — compact per-item format, not long prose per item
- [ ] Defaults to conversational feedback for a single item; switches to a structured/document format only when the user asks for something to keep or share
- [ ] Flags an off-brand register word that is not the literal example from the methodology (tests generalising the register principle, not recalling one worked example)
- [ ] On a mid-session correction (the user says a stated fact about the work is wrong), re-scopes the item without defending the earlier wording, and re-runs the five tests on the new shape rather than assuming it still passes
- [ ] Judges a short title together with its summary rather than flagging the title as vague in isolation when the summary supplies the specificity
- [ ] Holds the horizon-placement refusal under a leading, urgent, or "just your gut" framing, not just a direct ask — same answer regardless of framing
- [ ] When the user genuinely needs a horizon decided, or wants to know if an item's evidence is still current (not just whether the wording is good), redirects to craft-roadmap-builder rather than leaving the request unresolved
- [ ] No file is written during this skill's run — it is conversational-only
- [ ] memory.md updated with a run log entry
